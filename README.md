# 苹果箱数核对平台

几家市场联合核对同一果园苹果箱数的内部工具。合作社把已结清的入库 / 转仓 / 交货台账
批量入账，仓次级转仓单留在库里；对外只发放按果园汇总的**核对包**（去向 + 箱数），
市场凭核对包和各去向报数做一致性核对。

## 快速开始

### Docker Compose（推荐）

```bash
APP_SECRET_KEY=$(openssl rand -hex 32) docker compose up --build
```

访问 http://localhost:8000 。数据保存在名为 `ledger-data` 的卷里（容器内 `/data/ledger.db`）。

### 本地开发

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt -r requirements-dev.txt
APP_SECRET_KEY=dev .venv/bin/python run.py        # http://localhost:8000
.venv/bin/pytest                                  # 跑测试
```

## 业务流程

1. **上传台账**（`/upload`）：三个 CSV 一起上传，校验通过才入账；任一规则不满足，
   列出全部问题并**整批退回**（不入账）。
2. **下载核对包**（`/packages`）：选一个果园，下载 JSON 核对包。包里只有
   果园名、生成时间、按去向的箱数汇总（条目数只随去向数量变化）和签名，
   不含仓次、批次等明细。
3. **市场核对**（`/verify`）：上传核对包 → 页面列出各去向 → 填每个去向的报数 →
   提交。判定**仅凭核对包和报数**（不查库），结论为：
   - **相符**：整组报数可由同一套符合原账的产地流向解释；
   - **不符 · 总数差额**：报数合计 ≠ 账面合计，给出差额；
   - **不符 · 超限去向组合**：总数相等但某些去向报数超过账面供给，列出该组合及超出量。

## CSV 格式（UTF-8，首行表头，箱数为正整数）

| 文件 | 表头 | 说明 |
|---|---|---|
| 入库 | `仓次,果园,箱数` | 同一仓次只能归属一个果园 |
| 转仓 | `起仓次,讫仓次,箱数` | 起讫不得相同；只能在同果园仓次间转 |
| 交货 | `仓次,类型,去向,箱数` | 类型为 `交货` 或 `余箱` |

`samples/` 有一套可通过的样例，`samples/bad/` 有一套会因仓次差额被退回的样例。

## 校验规则（任一不满足即整批退回）

- 箱数一律正整数（按整箱记数）；
- 同一仓次只归属一个果园；经转仓相连的仓次必须同属一个果园；
- **仓次收发平衡**：入库 + 转入 = 转出 + 交货 + 余箱，有差额则指出仓次及差额；
- 交货和余箱合计**最多 4 个去向**（全库口径，含已入账数据）；
- 仓次名全库唯一；同一批文件按内容哈希去重，重复上传会被拒收。

## 核对包格式

```json
{
  "package_type": "orchard-reconciliation",
  "version": 1,
  "orchard": "果园A",
  "generated_at": "2026-11-23T15:22:05+00:00",
  "entries": [{"destination": "市场甲", "crates": 55}],
  "signature": "<HMAC-SHA256>"
}
```

签名密钥来自环境变量 `APP_SECRET_KEY`，市场侧篡改包内容会导致签名校验失败。

## 核对判定模型

把“能否由同一套符合原账的产地流向解释”建模为单源单汇最大流：
源 → 果园（容量 = 账面总箱数），果园 → 各去向（容量 = 账面该去向箱数），
各去向 → 汇（容量 = 该去向报数）。所有报数都被满足（最大流 = 报数合计）才可解释。
该网络中去向的唯一供给边是“果园 → 去向”，因此超限组合即报数超过账面供给的去向集合；
判定用最大流实现（`app/checker.py`），便于以后扩展更复杂的流向拓扑。

## 设计取舍与假设

- **每仓次单果园**：入库/转仓不逐箱跟踪果园，混合归属无法对账，因此直接拒收跨果园仓次。
- **批次自洽**：每个仓次的收发必须在本批内结清（“已结清”），仓次名全库唯一，
  因此果园归属与核对包汇总都是确定性的。
- **去向上限按全库口径**：已入账去向 + 本批新去向合计 ≤ 4。
- **核对无状态**：核对只依赖核对包 + 报数，不查库；包用 HMAC 签名防篡改。
- 台账存 SQLite（`LEDGER_DB` 可配置），上传大小限制 2MB。
